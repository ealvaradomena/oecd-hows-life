Comparing Current well-being with its demographic dataflows

  • Show All Code
  • Hide All Code
  • View Source

Question

The OECD disseminates Current well-being alongside specialized views by age, sex, and education level (OECD 2026c). Do these demographic dataflows contain distinct non-missing OBS_VALUE observations, or do their values already appear in the main Current well-being dataflow when records are matched on their shared SDMX keys?

The comparison is deliberately narrow: it evaluates record-key overlap and OBS_VALUE agreement. It does not establish equivalence of observation-status flags, other SDMX attributes, metadata, or presentation conventions.

Comparison Design

The three specialized dataflows use the same core demographic dimensions as Current well-being, but constrain the demographic codes differently. In the current SDMX structures, the specialized scopes are:

The project applies the same comparison procedure to all three specialized views. Records are matched on the canonical SDMX dimensions shared by the parent and specialized datasets: REF_AREA, MEASURE, UNIT_MEASURE, AGE, SEX, EDUCATION_LEV, DOMAIN, and TIME_PERIOD. A full join preserves matched keys as well as keys with a non-missing value on only one side. OBS_VALUE is compared using an absolute tolerance of 1e-10.

The resulting statuses have the following meanings:

  • Exact match: both sides contain non-missing values that agree within tolerance
  • Different value: both sides contain non-missing values that differ by more than the tolerance
  • Parent only: only Current well-being contains a non-missing value for the joined key
  • Child only: only the specialized dataflow contains a non-missing value for the joined key
  • Both missing: neither joined value is available

Importantly, parent-only and child-only are value-availability classifications, not independent tests of row presence. A record that is present with a missing OBS_VALUE is therefore treated the same as a missing joined value for this classification.

How to interpret parent-only records

The current comparison joins the complete parent snapshot to each specialized snapshot on their shared canonical dimensions. Because the specialized dataflows constrain demographic codes more narrowly than the parent, parent-only records include parent observations outside the specialized demographic scope as well as any other one-sided non-missing values.

Accordingly, the exact-match shares below describe the full joined record-key universe. They should not be interpreted as coverage rates for the specialized dataflows’ intended demographic scopes.

Subgroup-data caveats

OECD notes that indicators in the specialized age and education views are banded when the sample size is below 1,000 observations (OECD 2026a, 2026b). The Data Monitor also notes that some subgroup estimates pool multiple years, so a displayed period should not automatically be interpreted as a single-year estimate (OECD 2026d).

These source-level conventions are separate from the record-matching exercise below.

In the frozen project snapshot, all three comparisons report zero child-only observations, zero value disagreements, and zero both-missing joined keys. Every non-missing value available through the specialized demographic dataflows therefore has a corresponding non-missing value in Current well-being and agrees with it within the specified tolerance.

The reverse does not hold: Current well-being contains many parent-only values in each full join. Because the parent includes demographic combinations outside each specialized scope, those counts demonstrate that the parent is broader; they should not be read as missing-data rates for the specialized views.

Specialized-Only Records and Value Disagreements

No specialized-only non-missing values are detected in the frozen age, sex, or education comparisons. Likewise, no matched keys report OBS_VALUE disagreements beyond the 1e-10 tolerance.

This is the central result of the audit: with respect to the shared canonical keys and non-missing OBS_VALUE, the three specialized demographic views add no unique values in the frozen snapshot. This statement is intentionally narrower than saying that the specialized dataflows are identical to, or literal subsets of, Current well-being.

Interpretation and Limitations

The comparison supports a practical conclusion for this project: the specialized demographic dataflows do not contribute additional non-missing OBS_VALUE values beyond those already represented in Current well-being on matching keys. Their value lies instead in providing dedicated dissemination views with narrower demographic scopes and their own metadata and reliability conventions.

The result should not be generalized beyond what is actually tested. In particular, the audit does not establish equivalence of observation-status flags, methodological annotations, other attributes, or metadata. It also does not distinguish a genuinely absent row from a present row whose OBS_VALUE is missing when assigning the parent-only and child-only categories.
