The inventory above (Table 3) is computed from the data retrieved through the six corresponding SDMX dataflows rather than copied from the OECD Data Explorer interface.

It reports project-derived counts of observation rows, reference areas, and unique MEASURE codes in each local snapshot. These are properties of the downloaded SDMX files, not official headline counts of conceptual indicators.

In particular, the number of unique MEASURE codes in Current well-being should not be compared one-for-one with OECD’s statement that the overall How’s Life? database contains 80+ indicators across its six datasets (OECD 2026b, 2026a).

Snapshot provenance

New OECD downloads made by this project record a retrieval manifest containing the exact request URL, dataflow identifier and version, UTC retrieval timestamp, SHA-256 file hash, and available HTTP response metadata.

The project’s existing frozen-artifact integrity checks remain separate from this retrieval provenance.

The distinction matters because the downloaded snapshots constitute the actual data used as inputs to every downstream analysis in this project.

The dataflows are the SDMX dissemination objects through which the data are accessed; the downloaded observations themselves are the data being analyzed.

Snapshots

Here, a snapshot refers to the data returned by a particular OECD API request and saved locally when the retrieval pipeline is run.

A snapshot represents the data returned by that request at the time of retrieval. Because OECD datasets may subsequently be revised or otherwise updated, repeating the same request later may return different data.

Automated updates through the OECD API are possible but beyond the scope of this project.
