Why SDMX Matters

The OECD Data Explorer exposes a REST API based on the Statistical Data and Metadata eXchange (SDMX) standard (OECD 2025).

A reproducible request therefore requires both the dataflow identifier and knowledge of the data structure that defines its dimensions, their order, and the codes used to identify observations.

API access technicalities are addressed in what follows.

The joy of programmatic access to high-quality data

Why care about the OECD API? Because good empirical research begins with good data.

OECD statistical platforms provide high-quality, internationally comparable, well-documented statistics, while programmatic access makes it possible to retrieve those data directly and reproducibly.

More specifically, the OECD SDMX public service (sdmx.oecd.org/public) is the technical entry point to the OECD’s SDMX-based statistical infrastructure (OECD 2025).

Rather than a conventional user-facing website, it exposes web services through which OECD data and metadata can be accessed programmatically, including REST resources for observations, dataflows, data structures, codelists, and other SDMX objects (OECD 2025).

These services provide the programmatic infrastructure used to retrieve data disseminated through the OECD Data Explorer, making the service root primarily a developer resource rather than a platform intended for interactive data exploration (OECD 2025).

Direct access is especially valuable as AI increasingly mediates how people encounter official statistics. Important context can be lost along the information chain, making traceability, metadata, and connection to the original source increasingly important (Boarini and Tiati A Biscene 2026).

Registered How’s Life? Datasets

The Current well-being dataset serves as the primary example throughout the project.

The OECD Data Explorer (OECD 2026b) provides the following description of the How’s Life? database, of which Current well-being is one of six datasets:

The How’s Life? database is the one-stop shop for the 80+ indicators of the OECD Well-being Dashboard, covering social, economic and environmental outcomes that matter most for people, the planet and future generations. It consists of six datasets: current well-being, current well-being vertical inequalities, current well-being by age, educational attainment, sex, and resources for future well-being.

The project registers the corresponding six SDMX dataflows as follows:

Code 
registry |>
  dplyr::select(
    title,
    agency,
    dataflow,
    version
  ) |>
  knitr::kable()

Notice that the project pins dataflow version 1.1 for all six registered dataflows. This fixes the version of the requested dataflow, but it does not freeze the underlying data snapshot.

OECD datasets may be revised or otherwise updated while a dataflow version remains unchanged (OECD 2026e, 2026f).

Exact reproduction of the underlying data snapshot therefore requires preserving the raw responses together with the structural metadata used to interpret them.

The dataflow version should not be confused with the version of the associated Data Structure Definition (DSD), which is a separate SDMX object.

Dataset, Dataflow, and Data Structure Definition

In SDMX terminology, a dataset is an organized collection of data, whereas a dataflow is an abstract SDMX object according to which datasets are reported or disseminated (SDMX 2020).

A dataflow does not itself contain observations. Rather, it references a Data Structure Definition (DSD) that specifies the structure of the datasets associated with it and may constrain how that structure is used.

The DSD defines the dimensions used to identify observations, the measures that contain observed values, and the attributes that provide additional information needed to interpret them.

The DSD also specifies how these components are represented, including through codelists where their allowable values are coded. It therefore provides the structural blueprint that makes an SDMX dataset interpretable and machine-readable.

OECD’s API follows this SDMX architecture. Observations are retrieved through /data/ queries, while the OECD Data Explorer generates /dataflow/ structure queries that can retrieve the corresponding dataflow and referenced structural metadata (OECD 2025, 2026a).

OECD’s user-facing terminology is somewhat more flexible.

The OECD Data Explorer generally presents its statistical products as datasets, and the API documentation likewise uses dataset when describing the statistical resources users select and query, while also referring to the corresponding SDMX dataflows and dataflow versions (OECD 2025).

This is not a substantive contradiction but a distinction between user-facing statistical terminology and SDMX architectural terminology.

Throughout this website, I therefore use dataset for an OECD statistical product or the data being analyzed, and dataflow specifically for the corresponding SDMX object.

Constructing a Request

OECD API documentation explains how to construct data queries (OECD 2025).

In the generic API documentation, OECD refers to the version field as dataset version (OECD 2025).

Throughout this website, I refer to it more specifically as the dataflow version when discussing the corresponding SDMX object; the associated DSD is a separate, independently versioned object.

A data query follows this general syntax:

{Host URL}/{Agency identifier},{Dataset identifier},{Dataset version}/{Data selection}?{Optional parameters}

Where:

  • Host URL identifies the OECD API endpoint.
  • Agency identifier identifies the organization responsible for the dataset.
  • Dataset identifier specifies the dataset/dataflow to query.
  • Dataset version (optional) field identifies the version of the queried dataflow; if omitted, OECD uses the currently latest version. The associated DSD is a separate, independently versioned SDMX object (OECD 2025, 2026a).
  • Data selection determines which dimension values are returned.
  • Optional parameters can further specify the request, for example, by restricting the time period or selecting the response format.

For the Current well-being dataset, for instance, the request looks like this:

Code 
cwb_flow <- registry |>
  dplyr::filter(key == "current_wellbeing")

BUILD_OECD_DATA_URL(
  flow = as.list(cwb_flow[1, ]),
  cfg = cfg
)
[1] "https://sdmx.oecd.org/public/rest/data/OECD.WISE.WDP%2CDSD_HSL%40DF_HSL_CWB%2C1.1/all?dimensionAtObservation=AllDimensions&format=csvfilewithlabels"

The request above can be read as follows:

  • OECD.WISE.WDP is the OECD agency namespace used for this dataflow family (OECD 2026a).
  • DSD_HSL@DF_HSL_CWB is the dataflow identifier used by the OECD for Current well-being; despite the DSD_HSL prefix embedded in that identifier, the associated Data Structure Definition is a separate SDMX object named DSD_HSL (OECD 2026a).
  • 1.1 specifies the dataflow version requested by the project; the DSD has its own version and should be inspected through the structure metadata rather than inferred from the data-query URL.
  • /all requests all available data rather than a particular selection of dimension values.
  • dimensionAtObservation=AllDimensions asks the API to represent all dimensions at the observation level, producing a flat structure convenient for analysis in R.
  • format=csvfilewithlabels requests a CSV file containing descriptive labels alongside the underlying SDMX codes.

Thus, the request asks the OECD API to return all available observations from version 1.1 of the Current well-being dataflow in a labelled tabular format convenient for analysis (OECD 2025, 2026a).

The main pipeline makes one consolidated download per registered dataflow and caches the raw response.

Structural metadata are downloaded separately so that the observations and their SDMX structure can be inspected independently.

Let Data Explorer Construct the Key

For filtered requests, the Developer API control in Data Explorer exposes the corresponding Data query and Structure query after a selection is made.

Using those generated queries is safer than guessing the order or codes of SDMX dimensions (OECD 2025, 2026b).

For example, the following key requests the Current well-being Employment rate measure for all reference areas, with total age, sex, and education, in the employment domain:

https://sdmx.oecd.org/public/rest/data/OECD.WISE.WDP,DSD_HSL@DF_HSL_CWB,1.1/.2_1.PT_POP_Y25T64._T._T._T.HSL_2?dimensionAtObservation=AllDimensions&format=csvfilewithlabels

The dot-separated portion after the version is positional: each field corresponds to a dimension in the order defined by the current SDMX structure.

An empty first field leaves REF_AREA unrestricted; the remaining fields select MEASURE = 2_1, UNIT_MEASURE = PT_POP_Y25T64, total (_T) age, sex, and education, and DOMAIN = HSL_2.

This example illustrates why the structure matters: the meaning of a filtered key depends on both the dimension order and the valid codes defined for the dataflow.

The Data Explorer query builder provides a convenient way to obtain that information for a particular selection (OECD 2025).

Current Practice

The OECD Data Explorer is now the OECD’s current statistical dissemination platform. The former OECD.Stat service was taken offline on 1 July 2024, and legacy queries built around stats.oecd.org no longer work (OECD 2026d).

Current programmatic access should therefore use the OECD Data Explorer’s SDMX-based API and its associated query conventions (OECD 2025).

For efficient use of the service, OECD currently recommends caching retrieved data locally, avoiding unnecessary repeated downloads, and favoring consolidated queries where practical. API and browser-based data downloads are limited to 60 per hour (OECD 2026e, 2026d).

The project follows these recommendations by downloading each registered dataflow in a consolidated request and preserving the resulting raw response locally.

| **Version pinning does not freeze the data** | A fixed dataflow version does not guarantee an immutable data snapshot; OECD may update disseminated content while the dataflow version remains unchanged. | [@oecd_api_best_practices_2026; @oecd_data_explorer_platform_status_2026] |
